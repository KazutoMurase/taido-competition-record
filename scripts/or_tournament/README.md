# CP-SAT によるトーナメントCSV生成

設計案 `doc/or_tournament_csv_generation_design.md` の辞書式最適化を実装した、
既存スクリプトとは別の生成コマンドです。既存のディレクトリ名に合わせて
`scripts/or_tournament/` に配置しています。

リポジトリのルートで実行してください。

```bash
uv run --project scripts/or_tournament --locked python scripts/or_tournament/generate.py \
  2026_student_sub --source-csv ~/temp/players.csv --seed 1
```

Python 3.11 以降が必要です。初回実行時に専用の `.venv` が作られ、
`uv.lock` に記録した OR-Tools と依存パッケージがインストールされます。
プロジェクト本体を uv 管理へ移行する必要はありません。
依存を追加する場合は `uv add --project scripts/or_tournament <package>` を使えます。

## 入出力

`--source-csv` は既存コマンドと同様に複数指定でき、UTF-8/BOM、種目名の正規化、
コメント、団体メンバーからのチーム復元、CSVヘッダー、試合番号、三位決定戦用の
空行とSQLスキーマには既存処理を使います。出力先は次の通りです。

```text
data/<competition>/
  static/players.csv
  static/generate_tables.sql
  original/<event>.csv
  original/<group_event>_groups.csv
  original/generate_tables.sql
  generation_report.json
```

`competition` は `2026_student_sub` のようなディレクトリ名のみ指定します。
団体実戦にも新しい配置を適用します。団体法形・展開は既存と同じ出場順の
シャッフルと決勝4枠の採点表を出力します。
`groups.csv`、`event_type.csv`、`court_type.csv`、`title.txt` 等は生成しません。
団体名は出力先の既存 `static/groups.csv` から読み取ります。

全種目を一時ディレクトリで生成し、すべて成功した後に出力を更新します。
既定ではバックアップを作成せず、変更がある生成対象ファイルを上書きします。
`--backup` を明示した場合のみ、更新前に `generation_backups/<UTC時刻>/` へ
相対パスを保ったままコピーします。過去のバックアップは削除しません。
既存の無関係なファイルは保持します。バックアップを元の相対パスへ戻すと復元できます。
置換はファイルごとに atomic ですが、複数ファイル全体のトランザクションではありません。

## 採用した仕様

全体順位は **`rank_total` の正の整数のみ**を使います。
`rank_lastyear` はCSVに保持し、配置には使いません。
欠番を詰めず、空欄・0は順位なしとして扱います。
全体1〜4位の同順位は曖昧なためエラーです。5位以下の同順位や団体内の同順位は
同じ順位帯として扱います。空の団体ID同士は同団体とみなしません。

絶対条件は次の通りです。

- 全員ちょうど1枠、1枠には高々1人。枠数は人数以上の最小の2の冪。
- 1回戦のBYE対BYEは禁止。4ブロックの人数差は最大1。
- 全体1位=左上の一番上、2位=右下の一番下、3位=右上の一番上、4位=左下の一番下。
  ブロック内の具体的な角のスロットまで固定する。
- その種目にちょうど2人出場する団体は左右に分離。

2人の場合のみ、上位シードの上下指定を左右へ投影します。
3人の場合も4枠を使用します。1人以下の種目は既存処理と同様、生成対象外です。
上位固定と2人団体の左右分離などが矛盾した場合、条件を緩和せずエラーにします。
BYEは、以下の団体内順位に基づくsoftな優先条件で配分します。
全体シードの角の固定自体はBYEを保証しません。

以下の順序で各目的を最小化し、**最適性が証明された値を固定**して次に進みます。

1. 団体ごとの4ブロック人数が `floor(n/4)..ceil(n/4)` から外れる超過・不足の合計。
2. 同団体同士の1回戦の対戦数。
3. 全体5〜8位の4ブロック分散。
4. 同団体の全体1〜8位が同じブロックに入る超過人数（各ブロックで2人目以降）の合計。
5. 全体5〜8位の指定方向との差。
6. 全体5〜8位が割り当て先ブロックの上位シードと反対側の端から外れた人数。
7. 全体9〜12位、13〜16位……の順に、4ブロック分散、その後に指定方向との差。
8. Top8を8領域、Top16を16領域……に分散する階層的シード。
9. 団体内順位1〜4位、5〜8位……の4ブロック分散の偏差合計。
10. 団体を横断した同じ団体内順位の4ブロック人数偏差合計。
11. 団体内1位が1回戦を戦う人数、その最適値を固定して2位、3位……の順に評価。
    同じ順位の中ではBYE数が最大になるようにする。
12. 同じ団体内順位同士の1回戦の試合数。
13. すべての評価値を固定した解集合で、seedによるランダムな探索順から配置を選択。

追加した10〜12は、既存の全体順位と同団体配置の最適値を保ったまま適用します。
団体内1位が21人なら、ブロック人数は6・5・5・5人が理想です。
対象は `rank_group` のすべての正の整数で、欠番は詰めません。
空欄・0等は分散・同順位初戦の評価対象外とし、BYEは記載順位の選手を優先します。
例えば6人で団体内1位2人・2位3人・3位1人の場合、2つのBYEを両方1位に与えると
2位同士の初戦が発生するため、初戦回避を優先して1位と2位に1つずつ与えます。
上位全員のBYEを保証するものではありません。BYEがない種目では12を省略します。

5〜8位の通常の優先位置は、5位=左下の一番上、6位=右上の一番下、
7位=右下の一番上、8位=左上の一番下です。同団体の全体1〜8位が同じブロックに
入る場合、1〜4位の角は固定し、5〜8位の割り当てを入れ替えて分離します。
入れ替え後も、移動先の上位シードと反対側の端を優先します。
例えば8位が右下へ移動すると、右下の一番上（通常7位の位置）を優先します。
この条件は団体人数が3人以上の場合にも適用します。

同団体の全体1〜8位が5人以上いる等で完全分離できない場合は重複を最小化します。
端の枠の指定もsoftで、上位の評価を悪化させる場合は緩和します。
5〜8位が不在なら3〜6は省略し、反対端の評価は8枠以上で適用します。
追加した団体分離と端の評価はそれぞれ `top8_same_group_quarter` と
`global_rank_5_8_seed_position` として診断レポートに記録します。

分散の偏差は、各領域の人数がその順位帯の実人数の
`floor(n/領域数)..ceil(n/領域数)` から外れる超過・不足で評価します。
全体順位の方向は「左上・右下・右上・左下・左下・右上・右下・左上」の8周期です。
階層的シードは既定で有効です。`--no-hierarchical` で追加提案を無効にできます。
このオプションでも1〜4位の角の固定と5〜8位の反対端の優先配置は有効です。
Top8などは記載順位の閾値で対象者を選び、枠数までの2の冪で領域を分割します。

ここで「初戦」は設計書の数式通り、元のスロットで隣り合う2枠の1回戦を指します。
BYE通過後の初めての対戦まで同団体回避を保証するものではありません。
右側の画面表示は内部の木の順序と反転しているため、それを変換して方向を指定しています。

## 診断と再現性

`generation_report.json` に seed、OR-Tools版、入力のSHA-256、全スロット、
種目別人数、団体別ブロック人数、各段階の評価値と最適性ステータスを記録します。
追加目的名は `same_local_rank_quarter_balance`（同順位の偏差）、
`same_local_rank_first_round`（同順位初戦数）、`local_rank_<r>_non_bye`（順位rで1回戦を戦う人数）です。
`local_rank_summary` には順位別の `quarter_counts`・`first_round_matches`・`byes`・`non_bye`
を実際の配置から集計します。順位なしは `unranked` として人数を表示します。
seed未指定時は生成したseedを表示・記録します。
同じ入力順・seed・Python/OR-Tools環境で、時間内に完了した配置を再現できます。
探索は1ワーカーで、種目も順に処理します。厳密な一様抽選ではありません。

`--time-limit 60`（既定）は**種目ごとの各段階**の秒数制限です。
実行中は段階の開始・最適値と15秒間隔の進捗を標準エラーに表示します。
時間切れで `FEASIBLE`（未証明の暫定解）や `UNKNOWN` になった場合は終了コード1で
停止し、出力先は更新しません。必要なら `--time-limit 180` 等で再実行してください。
全段階の最適性を確認するため、大規模・制約の厳しい入力には時間がかかる場合があります。

ソルバーステータスと制限時間の意味は
[OR-Tools公式ドキュメント](https://developers.google.com/optimization/cp/cp_solver) と
[探索制限の説明](https://developers.google.com/optimization/cp/cp_tasks) に従っています。

## テスト

```bash
uv run --project scripts/or_tournament --locked python -B -m unittest discover \
  -s scripts/or_tournament -p 'test_*.py' -v
python3 -B -m unittest discover -s tests -v
```

上位シードの角と反対端、BYEを含む配置、団体総人数の均等化だけでは防げない
全体1〜8位の同団体重複と5〜8位の入れ替え、2人団体との競合、避けられない同団体初戦、
小規模の全列挙との最適値比較、80人/128枠、seedの再現性、時間切れ、
同じ団体内順位の分散・初戦回避、上位へのBYE配分と初戦回避の競合、
CSV/SQL互換性、既定でバックアップしない出力・明示的バックアップ・失敗時の出力保持を検証します。
